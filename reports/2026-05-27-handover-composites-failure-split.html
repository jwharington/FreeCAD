Handover Plan — Composite Failure Model Split

Date: 2026-05-27
Source branch: fem-orthotropic (rebased)
Confirmed scope: keep failure-model framework in FEM core; move only composite-specific failure models to ~/opt/FreeCAD-CompositesWB.

1. Context and Scope

This plan provides a concrete handover split between FreeCAD FEM core and Composites Workbench, with a function-level move map and phased execution plan for both repositories.

2. Extracts from Current Plan

  • From the rebased deep-dive report: Group C (laminated/draped shell plumbing) and Group E (post-processing failure metrics) are the key continuity anchors.
  • Open gaps retained as follow-up requirements:
    • expanded_mesh_tools.parse_12d not yet integrated in SEF path.
    • SEF uses fallback/default allowables in current state.
    • Insufficient dedicated FEM tests for new failure-model pipeline.

4. Minimal Core Interface (new)

register_failure_model(name: str, fn: callable, metadata: dict | None = None)
get_failure_model(name: str)
list_failure_models()
# optional: unregister_failure_model(name: str)
  • Core includes built-ins only (maximum_strain, maximum_stress).
  • Composites WB dynamically adds tsai_wu and hashin.
  • No FEM core import dependency on Composites WB.

5. Work to perform in ~/opt/FreeCAD

  1. Refactor failuremodels.py into built-ins + registry API.
  2. Remove composite models from core file.
  3. Update resulttools.add_stress_exposure_factor to resolve by registry and fail-soft on unknown model.
  4. Add tests:
    • femtest/app/test_failuremodels.py (max stress/strain + SEF monotonicity)
    • No composite-model assertions in core test suite

6. Work to perform in ~/opt/FreeCAD-CompositesWB

  1. Add composite failure provider module.
  2. Register provider at Composites WB init (fail-soft if registry unavailable).
  3. Implement laminate/material allowables adapter.
  4. Add tests:
    • deterministic Tsai-Wu/Hashin numeric tests
    • integration test proving registration visible to FEM registry

7. Integration Contract

  • FEM core must run without Composites WB installed.
  • Composites WB may extend FEM behavior only through registry API.
  • Unknown model names must never break FRD import or result pipeline.

8. Risks and Rollback

  • Risk: model-name mismatch between stored analysis options and provider registration.
  • Mitigation: support aliases (tsai_wu, composites.tsai_wu etc.).
  • Rollback: temporarily re-register composite models in core if provider integration blocks release.

9. Recommended Delivery Sequence

  1. FreeCAD PR: registry split + core tests.
  2. Composites WB PR: provider + registration + tests.
  3. Joint integration run (with and without Composites WB loaded).

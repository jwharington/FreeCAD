## 3. Cross-validation — variant (b) run; material-export defect fixed

Variant (b) (draped per-ply export, user-authorised) was solved on the
**same** flat plate and mesh as variant (a). After the force-unit and
result-mapping bugs it still disagreed by **~27%** (mean axial ux) — a
real, mesh-converged difference, not the old 32.8% measurement artefact.

A controlled experiment (per-element frame forced to a uniform identity
frame at runtime — no file changed, nextdrape untouched) isolated the
cause:

1. **Per-ply material export — root cause, fixed `1aa33763fe`.**
   `merge_single` baked each ply's rotation into engineering constants
   and `write_lamina_material_ccx` emitted `TYPE=ENGINEERING CONSTANTS`.
   A rotated ply is *monoclinic*: 9 orthotropic constants cannot carry the
   normal-shear coupling, so the rotated stiffness was silently replaced
   by a different (orthotropic) tensor — `Q̄11(45)`: 28404 → 15649,
   `Q̄66(45)`: 20419 → 9654, giving `A11` 58414 → 48210 MPa·mm (−18%) and
   an ~11% too-compliant laminate. Fix: retain the full rotated 6×6
   stiffness and emit `*ELASTIC,TYPE=ANISOTROPIC` (verified against
   CalculiX `test/aniso.inp` and `umat.f`; component order permuted).
2. **Backend mesh-edge frame — NOT a defect (rework reverted `00c2d5c7ec`).**
   `get_lcs` builds the per-element frame from the mesh triangle edge.
   That is fine: a QI stack is rotation-invariant in-plane, so any
   per-element frame gives the same membrane answer.  A rework to derive
   warp/weft from the drape field (`_field_frame`) was written, then
   withdrawn: it solved a non-problem and was O(elements × quads) and
   slow.  An earlier apparent frame “effect” was a cross-run mesh
   difference (8045 vs 8049 nodes at clmax 2), not the frame.

**Result (mean axial ux, draped vs QI):**

| clmax | nodes | before material fix | after material fix |
|---|---|---|---|
| 30 | 65 | 30.5% | 0.03% |
| 7.5 | 657 | 26.3% | 0.25% |
| 2.0 | 8045 | 27.6% | 1.59% |

The post-fix residual grows slightly with refinement and is investigated
as the composite-16-layer vs single-layer shell difference
(through-thickness / transverse-shear treatment) and/or draped-mesh
convergence — **not** the per-element frame.

**§7.6 tolerance agreed at 5%** (user, 2026-09-16); now asserted in

**Dead theories (still dead) — corrected note:** the rotation transform,
its sign, and the merge path were all correct. The defect was not in
*computing* the rotated stiffness but in *storing* it: the
engineering-constant form is lossy for off-axis plies.

1. "Rotated plies export halved G12" — that specific claim was FALSE

2. "Rotation direction/negation fix" — FALSE, reverted. Transform is

3. "Merge path contaminated" — FALSE. Merge `Q66'(45)` and merged QI

## 5. Lessons (the previous session was terminated for these)

1. **No throwaway scripts.** Verification/diagnostic code goes into committed `inspect_*` tools under `compositestests/` (house pattern). Violated three times.
2. **Run tools with output redirected to a file, then inspect the file** — do not inline-grep tool output.
3. **Submodules (nextdrape, AnalysisSitus, …) are read-only** without explicit per-change permission from the user. nextdrape carries the user's uncommitted in-flight work (`40a7f9a`, baseline12, `FC_DRAPE_DUMP_DIR` aid in `drape_backend_nextdrape.py` — untouched, leave it so).
4. **Never reason your way to a diagnosis** — the user said so twice. Empirical verification first; every "verified" theory claimed this session was wrong until disproven.
5. **`str.replace` in scripted edits fails silently** — one PRD step-list rewrite was silently lost and had to be repaired. Assert anchors or use the `edit` tool.
6. **Stale `.pyc`**: after editing Composites python, purge `src/Mod/Composites/**/__pycache__` *and* `build/debug/Mod/Composites/**/__pycache__` (build-install + purge) or stale code executes silently.
7. **FEM result mapping**: result value lists are ordered by `result.NodeNumbers` (the result mesh is *compacted* by `importCcxFrdResults`; coordinates come from `result.Mesh.FemMesh.Nodes`).
8. FreeCADCmd intercepts unknown CLI flags — inspect tools take env-var options (`QI_CONV_*`), not argparse flags.
9. Testing discipline: relevant modules only, never the full suite unprompted; never widen tolerances or touch pinned assertions without explicit user approval.

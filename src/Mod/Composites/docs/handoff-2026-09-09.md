## Solver overhaul — the model to preserve

`TransferRosetteFP._solve` is a **closed-form phase-1 frame solve**:

- Both sides measured from rosette frames (master rosette vs the
  transfer's own LCS) — never from drape fields. Drape-lattice boundary
  rows are boundary-snapped and made the residual step-quantised: no
  root-finder can meet it (the old bracket exit masked this).
- Per-sample residuals **fold mod π** (undirected warp; the 180°
  anti-parallel case sat on the atan2 branch cut).
- The residual is exact-linear in the angle (slope −π/180 per degree:
  `Angle` rotates the frame about the very normal the measurement uses);
  the root is one step away, **wrapped** into the principal period via
  `wrap_angle` (never clamped — fabric symmetry).
- `solve_rosette_angle` (AlignFibre, texture-coordinate residual) is a
  probe-seeded secant with the same wrap.

Do not reintroduce per-iteration re-draping of the attachment shell.

## Environment / workflow facts (new or re-confirmed)

- **New files need a CMake reconfigure** to enter `CompositesScripts`
  (content edits only need the build). `touch CMakeLists.txt` or run the
  build script after adding files; the build script's auto-reconfigure
  does not trigger on new files.
- `compositestests/run_one.py` — run one test case with the log retained
  (`COMPOSITES_TEST_ID=... FreeCADCmd -c "exec(open(...).read())"`);
  `run-tests.sh` deletes its log on success, which hides PROFILER
  output when profiling a single test.
- `Console.PrintMessage` goes to `/tmp/freecad.log`, not the MCP tool
  output; `print()` goes to the tool output. When probing from MCP,
  prefer `print` (or check the log).
- FeaturePython gotchas confirmed this session: a bare Shape assignment
  drops the shape's placement (sync `Placement` too); a recompute may
  clear `Touched` without calling Python execute when the object was
  left touched mid-sweep by another object — poll state, not presence.
- `App::PropertyLinkHidden` is the sanctioned way to hold a reference
  that must not join the DAG (solve references, back-references).

### 1. Rosette VP-attach regression pin (FreeCAD, `a40a63d6ce`)

Closes the last open item from `handoff-2026-07-15.md` (its item 3,
annotated DONE there). The pin:
`TestCompositeExamplesSmoke.test_rosette_vp_switch_survives_attach_and_raise`
(GUI-gated, seam example — exercises rosette-VP-attaches-before-shell AND
mid-recompute transfer rosettes): every rosette's display-mode SoSwitch
must point at its symbol (`whichChild == 0`) after
`FreeCADGui.updateGui()` (so the deferred GUI finalization has run) and
again after `raise_render_order`'s re-parenting.

Mechanism established from FreeCAD C++ (`src/Gui/ViewProvider*.cpp`): the
mode switch **is** the visibility mechanism (`hide()` writes
`whichChild = -1`; `isShow()` is literally `whichChild != -1`), and a VP
attaching after the GUI's display bookkeeping initialised can transiently
sit at NONE — node present, symbol gone. Landed hardenings in
`ViewProviderRosette.attach` (features/Rosette.py):

- the Standard display branch is **named** (`RosetteStandardMode`) — pivy
  returns a fresh Python wrapper per `getChild()`, so node identity must
  be established C++-side by name, never with `is`
- the switch is pinned at attach, re-pinned deferred (QTimer singleShot,
  exception-guarded for closed documents) and after `raise_render_order`
- a rosette with `Visibility == False` is never pinned (hiding must stay
  hiding)

Sensitivity proven (forced -1 → assertion fails); verified repeatedly in
the GUI via MCP; headless rosette + example suites 45 PASS / 3 GUI-gated
skips.

### 2. nextdrape wide_rect: stress shape, instrumentation, node-cap fix

(`7421b3b` shape + test + diagnostics, `3cb451f` root-cause doc,
`b12647e` fix — full working notes in nextdrape `todo.md`.)

- **Shape**: `wide_rect` in `TestHelpers` registry — cylindrical 800×100
  (arc × axis) panel on an adjustable radius (initially 10000 mm,
  near-flat), canonical seed at panel centre, fibres along the
  circumference. Covered by `drape_cli --all`.
- **Test**: `BaselineShapes.WideRectCoverageAndShearAcrossOffsetAngles` —
  radius {10000..800} × seed offset {0..90° step 15} = 49 solves;
  asserts status, coverage ≥ 0.985, strain, quad density ≤ 1.30, and
  shear ≤ 1° in the flat limit (measured ~5e-12°; shear grows ~1/R at
  oblique angles, max 3.0° at R=800).
- **Defect found**: coverage collapsed to 0.659 at oblique angles on
  R=10000 (frontier stops short mid-panel in a diagonal wedge at both
  short ends) while the flat 800×100 panel was clean at every angle.
  Root cause: `ComputeFrontierConfig` derived the frontier node cap from
  the **axis-aligned bounding box** — on a shallow-arc cylinder the
  box's extent collapses to the sagitta (32 mm vs the 800 mm arc), so
  the cap fired at ~83% coverage and froze the wavefront mid-advance;
  its un-attempted successors are the diagonal wedge. Diagnosed with
  read-only evidence + a pitch sweep that confirmed the 1/pitch² cap
  scaling in advance (pitch 8 → 0.9977, pitch 2 → 0.7898).
- **Fix** (user-approved): the cap now uses the true surface area
  (`BRepGProp::SurfaceProperties`, same integration QuadBuilder already
  uses); the 3x slack explicitly absorbs failed-attempt records.
- **Kept instrumentation** (DIAG_TP / ND_QUAD_DEBUG precedent):
  `solve_rej_*` rejection-reason counters in SurfaceProjection surfaced
  in the DIAG_TP line, `failBoundary`/`failCollision` in
  `LatticeNodePlacerDiagnostics`, and `ND_SOLVE_DEBUG` env-gated prints
  at the border-clamp/inside-tol/strict-bounds sites.
- **Verification**: sweep 49/49 green; zero regressions by stash-
  baseline (identical failure sets pre/post on the drape suites; the
  6 known BaselineShapes failures and the mould assertion are
  pre-existing and out of scope); `drape_cli --all` coverage identical
  to pre-fix on all 13 shapes.
- **Known cosmetic wart** (recorded, unfixed): the
  `frontier-safety-fuse` diagnostic is emitted even on successful
  saturation — `stoppedBySafetyFuse` initialises true and is only
  cleared by the stagnation branch, so normal saturation still reports
  it. Every baseline shape shows `diagnostics=1` for this reason.

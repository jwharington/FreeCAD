## What was done (mechanism summary)

### nextdrape C++ (`src/3rdParty/nextdrape`, commit 93a6b79 + 5b4ef50)

- `QuadBuilder::TryRevalidateQuad` — quads pushed against not-yet-placed boundary proxy slots are re-validated when the snap fills the slot (called from both snap paths in `LatticeFrontierPhase2.cpp`: `RunSnap` success path and `SweepSlot`).
- Face budget is area-weighted (real quad area, not flat pitch²); `TryCreateQuad` returns attempted-cell area even on rejection so `LatticeFrontierPhase1`'s per-face accumulator can trip the wrap gate.
- `IsCollapsedSliver` (min edge < 15% pitch) keeps collapsed cells invalid.
- Strain/shear are boundary-aware: edges incident to `BoundarySnapped` nodes are trimmed cuts, excluded from strain; cells touching the trim report no shear.
- Wrap guard: `LatticeFrontierPhase1` cell processing consults `facePlacedArea` accumulator vs `QuadBuilder::FaceSurfaceArea(faceIdx) × 1.02` and declines cells on saturated faces. NOTE: only rosette VP roots (SoFCSelectionRoot) are direct children of `getSceneGraph()`; shells are nested — the gate is in Phase-1, not scene-order based.
- Baseline `cyl` at pitch 20: coverage 0.73 → 0.98; cone max_strain 4.31 → 0.0001; closed cyl 899 quads/4.55 wraps → 303 quads/~1 wrap; **15 pre-existing nextdrape test failures resolved, 3 remaining are pre-existing** (CoverageGeometry.BentPlateDiagnosticsPopulate, CutWireEngine.HolePanelProducesCutWireDiagnostics, ExactSolverRobustness.FlatPanelLatticeNodeDistances) + mould `splitNonPlanarShells` assertion abort is **pre-existing** (verified on clean tree — do not assume regression).

### Rosette visibility (FreeCAD side)

- `RosetteSymbol.py`: DELAYED_BLEND deferred pass + `SoDepthBuffer(test=False, write=False)`; white circle, bright red/green axes, 3 px lines. CAUTION: depth-write is disabled when depth-test is off (GL rule); draw order within the deferred pass still matters — hence the reorder below.
- `ViewProviderRosette._hide_datum_symbology`: hides the LCS datum **and its Origin features** (axes/planes drew as grey flags).
- `ViewProviderRosette.raise_render_order()`: moves the rosette's `RootNode` to the end of `activeView().getSceneGraph()` — required because a rosette created *before* its shell loses the deferred-pass draw-order race to the weave shader.
- `VPCompositeShell._raise_rosette_render_order(vobj)`: raises ALL document rosettes; called at `attach` and after every `reload_shader`/weave injection (proxy hook in `CompositeShell.py` after `_set_shell_transparency(vp)`).
- Examples no longer call raise_render_order (guarded stubs removed); headless runs no-op through stubs.

### Examples

- `transfer_rosette.py`: 30° bend (BEND_ANGLE), fabric at FABRIC_OFFSET_ANGLE=30 (bend rosette solves to −59.7°), bend extends outward. DRAPE_PITCH=2.0.
- `cyl_sphere_seam.py`: NEW — cylindrical panel + spherical cap, same radius 50, seam arc shared, fabric at 30° (transfer solves ~41°; docstring records the strain cost of a 30° crossing on a spherical head). Cap stops at 75° latitude (polar opening). ## Environment / workflow facts (learned or re-confirmed)

- **FreeCAD MCP dies often**: connection refused after heavy use; restart with `~/.pi/agent/skills/freecad-dev/scripts/start-freecad-mcp.sh [--kill]`. Long example builds exceed the MCP tool timeout — the call keeps running in FreeCAD; wait (sleep 120-240) then inspect with a fresh call.
- **Tests run from the pixi env** (`.pixi/envs/default/Mod/Composites`), NOT build/debug: after editing Python sources you must run `build-install-freecad.sh` (full install), not just `CompositesScripts` (which only copies to build/debug). Symptom of forgetting: suite tests your old code.
- **GUI process keeps old Python modules**: after rebuilds, restart FreeCAD (start script `--kill`) or `importlib.reload` every touched module; symptom: edits "don't take effect" in the GUI.
- **MCP screenshot grab intermittently segfaults** (QOpenGL framebuffer) killing FreeCAD — known-issues #9. If FreeCAD dies during a view capture, just restart and re-show.
- Example builds of cyl_sphere_seam take ~4 min in GUI (transfer solve iterations); headless ~30 s. FreeCADCmd probe pattern: `sys.path.insert(0, "/home/jmw/opt/FreeCAD/build/debug/Mod")` then `from Composites.compositeexamples import runner` — but ensure build/debug copies are current via CompositesScripts target, or install first.
- Helper `raise_render_order` is headless-guarded at call sites via `getattr(vo, "Proxy", None)`.
- `run-tests.sh <module>` timings file: latest `/tmp/freecad-test-timings.*`; only module-level names resolve.

**Update (2026-09-09):** implemented and GUI-verified — see the "Work

`handoff-2026-09-09.md`. The PRD text below is retained for the design
rationale.

`src/Mod/Composites/docs/stiffener_composite_shell.md` — fully grilled,
decision log complete, checkbox plan §12 ready for implementation. The
stiffener (currently pure geometry — no laminate, no rosette) becomes a
StiffenerCompositeShell: configured with its own `Laminate` + `Rosette`
(standard Composite::Shell property names), split into web shell (own
laminate) + foot shell (combined stiffener⊕panel laminate) with
symmetric solved transfers at the fold (ADR-0001 machinery reused via
SeamCompositeLaminateFP wired as Master=panel, Attachment=web shell,
SeamRegion=foot shell). Weave exclusivity via re-supporting the panel on
`make_stiffener`'s existing support remainder. Key grill decisions: two
modes only (geometry-only / full composite, loud failure on partial
wiring); foot strip optional and follows the profile (graceful
degradation when the profile loses its bonding flange); filters hidden
in composite mode (native faces coincide with weaves). Docs: `CONTEXT.md`
(Stiffener joint terms), `adr/0002-stiffener-region-split-and-render-ownership.md`.
Note: existing T-section stiffener tests are geometry-only and stay
passing; composite mode requires a bonding flange (base edge with
extent).
